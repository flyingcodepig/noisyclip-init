# Second-round baseline (B0)

This directory preserves the submission-version CLIP baseline, reported by the project owner as validated at approximately **78–79 points**. Uploading this snapshot does not constitute a new training or evaluation run.

The Python, Bash and configuration files in `code/` are copied without algorithm or hyperparameter changes. `source_manifest.json` records their original SHA-256 hashes. The repository's existing `src/noisyclip` implementation remains separate from this baseline.

## Method

- OpenAI CLIP ViT-B/32 visual backbone, 448-pixel inputs and a 750-class cosine head.
- Gated foreground/background patch contrast pooling.
- Exact-duplicate candidate labels, GCE, Mixup/CutMix, feature anchoring, L2-SP and trusted supervised contrastive learning.
- Two-stage training: 4096 steps, then 2048 steps with a 3072-step learning-rate schedule.
- Single-model four-view prediction followed by query graph propagation and balanced readout.

## Files supplied separately

This is a **code-only snapshot**. It does not publish competition images, dataset indices, candidate-label arrays, model weights, predictions or reports. Obtain the authorized original files and preserve their ordering:

```text
code/data/train_index.json
code/data/test_names.json
code/data/official/train/<class>/<image>
code/data/official/test/<image>
```

The training script generates candidate-label arrays from the original TRAIN images. Training feature caches are generated by `prepare_training.py`; original checksum checks remain enabled. The bundled `weights/clip-vit-base-patch32/` contains configuration only; `fetch_weights.py` downloads and verifies the official initialization.

## Run

Use Linux or WSL with Bash and the CUDA environment specified in `code/requirements.txt` and `code/environment.json`. Training defaults to four GPUs; inference uses one GPU. The implementation is specific to 750 classes and 37444 TEST images.

From this directory, after preparing the original data and indices:

```bash
python -m pip install -r code/requirements.txt
bash code/run_train_all.sh
```

To use an existing final checkpoint, supply its absolute path explicitly:

```bash
MODEL_PATH=/absolute/path/model.pt \
RESULT_DIR="$PWD/results" \
INFERENCE_CACHE="$PWD/code/inference_cache" \
bash code/run_predict.sh
```

Generated CSV/ZIP files are local outputs and must not be committed.

## Preserved implementation limitations

- `predict.py` refuses to overwrite an existing `test.npz`; use a fresh `INFERENCE_CACHE` for a repeat inference run.
- A stage-two restart checkpoint must reside inside `code/`, as required by the existing training assertion. The default `code/runs/stage1/last.pt` satisfies this requirement.
- Historical training records used a split first-stage launch; the submission script starts the first stage directly to step 4096. Bitwise equivalence has not been checked in this upload.
- The code-only snapshot omits original data indices and checkpoints, so it is not runnable until those separate inputs are supplied.

Future method changes should be made separately so this branch remains a reference for B0.
