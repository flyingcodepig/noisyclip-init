# 代码质量与合规门禁

## 1. 合并前静态门禁

```bash
ruff check src tests
ruff format --check src tests
mypy src
pytest -q tests/unit
```

要求：

- 公共函数、方法和数据类全部类型标注。
- 公共 API 有 docstring，明确张量形状、dtype、范围和异常。
- 禁止裸 `except:`、静默吞异常和在库代码中使用 `print`。
- 禁止通配符导入、隐式全局状态和硬编码绝对路径。
- 配置中的未知字段必须报错，不能静默忽略拼写错误。

## 2. 单元测试最低覆盖面

- 类别映射：非连续四位 ID、重复目录、非法格式。
- 数据划分：确定性、每类样本保留、极小类别失败策略。
- 图像读取：正常图、截断图、不可读图。
- 分类头：形状、归一化、温度边界。
- LoRA：注入位置、冻结参数、合并等价性。
- 原型：缺类、零权重、异常值、归一化。
- 可信度：类内排名、常数信号、NaN、单样本类别。
- ELR：按 sample_id 更新、恢复、warmup。
- 一致性：teacher detach、强视图为空时行为。
- 提交：行数、类别、文件名、重复和顺序。

核心模块建议行覆盖率不低于 85%，但覆盖率不能替代边界测试。

## 3. 集成门禁

```bash
pytest -q tests/integration
```

至少包含：

1. 人工构造的 3 类小数据集训练两个 batch，loss 有限且参数按预期更新。
2. B0、B1、B2 配置都能组装，关闭模块不改变基线行为。
3. 中断保存并恢复后，下一步输出在设定容差内一致。
4. LoRA 合并前后预测一致。
5. test manifest 一旦进入训练 DataLoader，预检必须失败。
6. 运行目录存在时拒绝覆盖。

## 4. 训练前强制预检

以下任一失败都不得启动 GPU 训练：

- 官方训练根、测试根、运行输出根未解析为不同目录。
- train/val/test manifest 存在路径或哈希交集。
- 类别数量与配置不一致，或 class ID 不是四位字符串。
- CLIP 模型名或权重来源不在 allowlist。
- 数据 digest 与本次 manifest 不一致。
- 输出目录已存在或剩余磁盘不足预计 checkpoint 需求的 2 倍。
- CUDA 不可用、GPU 显存不足最低配置、驱动/运行时不兼容。
- B0 出现 backbone 可训练参数，或 B2 出现未授权参数。
- 使用了外部数据路径、人工 clean list 或 test 派生缓存。

## 5. 训练中灾难保护

- 每一步检查 total loss 和梯度是否有限；首次 NaN/Inf 立即停止并保存诊断，不继续污染权重。
- 默认梯度范数裁剪；连续多步超过阈值触发失败。
- 样本状态和 checkpoint 使用临时文件 + fsync + 原子 rename。
- `best.pt` 不直接覆盖，先写版本文件，再更新指针/副本。
- 每轮检查实际可训练参数集合没有变化。
- 每轮验证类别映射 digest 未变化。
- 磁盘剩余空间低于安全阈值时停止进入下一轮。
- 训练进程不得删除原始数据、旧 run 或最后一个有效 checkpoint。

## 6. 实验有效性门禁

实验结果只有满足以下条件才可进入比较表：

- 完整写入 resolved config、代码版本、环境快照和数据 digest。
- 训练正常完成或明确标记为早停，不是异常中断。
- 使用同一验证清单和主评价协议。
- 指标来源于保存的最佳 checkpoint 重新评估，而非仅引用训练日志瞬时值。
- 至少保留 per-class 指标和混淆矩阵。
- 上限模块初筛为单因素实验；组合实验必须注明依赖的已通过模块。

## 7. 最终提交门禁

- 模型包仅包含一个推理模型。
- 模型使用官方 CLIP ViT-B/32 权重派生，来源和哈希已记录。
- 推理预处理与训练配置一致，且不依赖网络或外部 API。
- CSV 行数等于测试图片数，每个文件恰好出现一次。
- 类别字段满足 `^[0-9]{4}$` 且存在于 `class_to_idx.json`。
- 输出文件名、大小写、扩展名与官方列表完全一致。
- 在干净容器中完成一次从模型加载到 CSV 校验的端到端演练。
