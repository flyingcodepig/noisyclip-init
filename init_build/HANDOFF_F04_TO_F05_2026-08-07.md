## 1. 用户目标与总体方法论

用户参加的是“面向噪声标签数据的细粒度图像识别鲁棒微调”比赛，目前聚焦初赛。

用户已经确定的研究方法论：

1. 先完成一条保守、合规、可复现的主路线。
2. 主路线按单变量方式逐步加入提升上限的方法。
3. 每项技术必须通过多评价角度的消融实验判断是否保留。
4. 不以单次最高 Top-1 作为唯一依据；同时观察 Macro、困难类别、后四分位类别、稳定性、校准、漂移、显存和训练时间。
5. 每次实验只改变一个核心变量，使用固定数据划分、固定评价代码和固定随机种子序列。
6. B0-B6 主线稳定以后，才进入 U1-U6 上限实验。

技术主线：

| 阶段 | 技术 | 解决的问题 |
|---|---|---|
| B0 | 冻结官方 CLIP + Linear Head | 建立无鲁棒机制的最低可复现基线 |
| B1 | Cosine Head + 单原型初始化 | 改善 CLIP 表征与分类头的几何匹配 |
| B2 | 后层 Attention LoRA | 有限适配细粒度视觉差异，同时控制灾难性遗忘 |
| B3 | 类内归一化多信号 trust 连续加权 | 减弱疑似错标样本影响，同时避免误删困难样本 |
| B4 | ELR | 抑制训练后期记忆噪声标签 |
| B5 | 冻结 CLIP teacher 特征锚定 | 限制特征漂移和灾难性遗忘 |
| B6 | 弱/强增强一致性 | 利用不依赖原标签的稳定性信号 |
| U1 | 严格门控软伪标签 | 纠正长期与视觉证据冲突的疑似错标 |
| U2 | 课程学习 | 控制不可信样本参与训练的节奏 |
| U3 | 多原型 | 表达单类内部多模态结构 |
| U4 | 类别均衡 | 仅在 F05 证明类分布不均衡时考虑 |
| U5 | trust 梯度/约束 | 控制可信度估计的形状和稳定性 |
| U6 | 自适应分区 | 替代固定阈值，但风险和复杂度更高 |

## 7. 矩池云存储与快照

文件系统：

```text
/ 和 /opt：overlay，200G，总使用约45G，剩余约156G
/mnt：fuse.fx，405G，总使用约52G，剩余约354G
```

矩池云语义：

- `/mnt` 是持久化网盘，实例释放后保留。
- `/opt`、`/root` 属于机器环境，实例释放默认清除。
- “保存环境”会保存除 `/mnt` 以外的机器文件变更，因此包含 `/opt` 和 `/root`。
- `.snap` 存储在 `/mnt` 并占用网盘容量。
- `.snap` 不得直接从网盘删除，应在“我的环境”管理。
- 环境恢复受区域、CUDA和主机类型兼容性约束。

已保存快照：

```text
名称：noisyclip-f04-808b7a6-native-v1
状态：用户已报告保存成功
预计大小：43GB
```

该名称为 31 个字符，符合矩池云 32 字符限制。

快照包含 `/opt/noisyclip-data-ro` 数据副本、普通用户 Conda 环境、CLIP 缓存、不可变源码副本等，因此约 43GB 是合理的。不要为每个实验都创建 43GB 快照；该快照作为 F04 基础环境，实验产物另行备份到 `/mnt/noisyclip-persist`。

## 8. 服务器固定路径与权限模型

矩池云永久原始数据：

```text
/mnt/noisyclip-data/init/train
/mnt/noisyclip-data/init/test
```

矩池云 `/mnt` 挂载参数：

```text
fuse.fx rw,nosuid,nodev,relatime,user_id=0,group_id=0,allow_other
```

对 `/mnt` 做的普通用户写入探针失败了：`noisyclip` 用户能够在 mode 0555 的 FUSE 目录中写入。这说明不能依赖 `/mnt` 的 POSIX mode 实现只读隔离。

因此创建了本机 overlay 数据副本：

```text
/opt/noisyclip-data-ro/train
/opt/noisyclip-data-ro/test
```

权限策略：

- owner/group 为 `root:root`。
- 目录为 `0555`。
- 文件为 `0444`。
- 正式进程使用 `noisyclip` 用户。
- preflight 已确认普通用户视角下 train/test 不可写。

其他固定路径：

```text
不可变源码：/opt/noisyclip-src-808b7a6
普通用户环境：/opt/noisyclip-env-808b7a6
训练输出：/opt/noisyclip-runs
CLIP缓存：/opt/noisyclip-cache/xdg
持久化记录：/mnt/noisyclip-persist
```

`/opt/noisyclip-runs` 必须由 `noisyclip` 用户可写；源码、环境和已验证权重应由 root 持有并对普通用户只读。

## 14. 服务器实验运行规则

1. 永远使用 `noisyclip` 用户运行正式任务。
2. 服务器不直接改代码；所有代码改动在本机完成、测试、commit、推送，再部署固定 commit。
3. 一张 A100 同时只运行一个训练任务。
4. 不在实验中途升级 PyTorch、Pillow、CLIP、ruff、mypy 或其他依赖。
5. 不在实验中途更换权重文件。
6. 每个 run ID 唯一；已有 run 目录不得覆盖。
7. 每个实验保存 resolved config、环境快照、commit、数据 digest、随机种子和指标。
8. checkpoint 成功后才提交 sample state。
9. 任何 NaN/Inf、类别映射变化、数据 digest 变化、非授权参数梯度都立即停止。
10. 每个重要实验结束后立即把关键产物复制到 `/mnt/noisyclip-persist/runs/<run_id>`。
11. `/opt` 剩余空间低于 50GiB 时停止新实验并整理已备份产物。
12. 删除 ZIP、旧 checkpoint、旧 run 或快照属于有损操作，必须先核验备份并得到用户明确确认。

初始 DataLoader 建议：

```text
num_workers=8
pin_memory=true
prefetch_factor=2
persistent_workers=true
```

服务器有 12 CPU 核和 90GiB RAM。初始不把 worker 直接设为 12，要给主进程和系统留资源。S0 根据 GPU 利用率再决定是否测试 6、8、10 workers。

## 17. 已知风险与后续关注点

### 17.1 FUSE 与数据副本

`/mnt` 对大量小文件的元数据和读取可能较慢，且 `du -sh` 可能因 `st_blocks=0` 显示目录大小为 0。使用：

```bash
du -sh --apparent-size <path>
```

或文件长度合计、内容哈希，不要把 `du=0` 当成空目录。

### 17.2 快照体积

基础快照约 43GB。后续如果 `/opt/noisyclip-runs` 产生大量 checkpoint，再保存环境会显著增大 `.snap`。应先把实验关键产物备份到 `/mnt`，并且只在里程碑创建快照。

### 17.3 `/opt` 容量

当前约剩 155GiB，足够近期阶段，但不适合无节制保留全部消融 checkpoint。通过 `keep_last_checkpoints=2`、及时备份 best 模型和单实验清理策略控制空间。

### 17.4 原生环境与原Docker计划不同

实际使用 PyTorch 2.6/CUDA 12.4，而原计划曾假设更高版本。所有代码测试和真实 CLIP 加载已经在当前环境通过；不要为了追求原计划版本而升级，除非新 commit 和 S0/B0 全部重新验收。

### 17.5 文档编码

某些 Windows PowerShell 读取中文 Markdown 时可能显示乱码，这是控制台编码问题，不一定是文件损坏。使用 UTF-8 编辑器或显式 `-Encoding utf8`。
